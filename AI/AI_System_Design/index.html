Architecture Intent

Version 5c: places AI Design Factors immediately after Architecture Intent so the architectural considerations are established before downstream design and architecture outputs. The factors remain organized into Model & Data, Agent Runtime, Identity & Trust, Security & Operations, and Governance & Assurance.
Purpose: design an AI system by first defining the operating model, risk boundary, data posture, agent authority, and design trade-offs before selecting cloud services or model providers.

Model-Aware Architecture

The model is a capability inside a distributed system, not the whole system. Design identity, data flow, retrieval, orchestration, observability, and fallback around it.

Zero Trust AI Access

Prompts, retrieved context, embeddings, memory, tool calls, generated outputs, and logs are treated as protected assets. Apply continuous identity, device, location, risk, data-sensitivity, and action-context checks before model access, retrieval, memory use, or tool execution — using established Zero Trust and Conditional Access patterns from your identity provider (e.g., Microsoft Entra ID, Okta, AWS IAM Identity Center).

Trade-Off Driven

Every design choice should explain the selected option, the rejected option, and the cost, latency, quality, privacy, or operational impact accepted.

Least-Privilege Agent Authority

Agents should never inherit broad human or platform permissions. Tool access must be scoped, authorized, logged, and revoked when risk changes.

Grounded and Evaluated Outputs

Use retrieval, citations, validation, test sets, red-team scenarios, and human review where AI output must be trusted or acted upon.

Operational Resilience

Design the AI platform as an operations-grade system with capacity controls, cost governance, lifecycle management, model rollback, and measurable service health.

Threat-Informed Design

Map design controls to the NIST AI 100-2e2025 adversarial-ML taxonomy: high-level attack classes include evasion, poisoning, privacy, and—within GenAI—misuse. Test representative techniques and objectives such as prompt injection, backdoors, model extraction, and membership inference, aligned with MITRE ATLAS and OWASP Top 10 for LLM Applications 2025 (v2.0).

Graceful Degradation

When model, vector index, tool API, or guardrail services fail, the system should degrade safely rather than fail open or take uncontrolled action.

Incomplete Defense Acknowledgment

Prompt injection, particularly indirect injection via external content, has no known complete defense as of 2025. Defense-in-depth reduces risk but cannot eliminate it for high-assurance contexts requiring human approval gates.

AI Design Factors

Architecture taxonomy: design the AI system across five connected domains — Model & Data, Agent Runtime, Identity & Trust, Security & Operations, and Governance & Assurance. These factors are architectural concerns, not vendor product categories.

Model & Data

Model & Inference

  • Provider/model class, hosting, region, context window, latency, routing, fallback, throughput, and cost controls.
  • Trade-off: quality and reasoning depth versus latency, cost, resilience, and data-handling restrictions.

Retrieval & Grounding

  • RAG architecture, source ingestion, chunking, embeddings, ranking/reranking, graph relationships, citations, provenance, and freshness.
  • Authorization must occur before protected content enters model context.
  • Trade-off: grounded evidence versus retrieval latency, complexity, and leakage risk.

Memory & State

  • Working, episodic, semantic, procedural, enterprise/shared, audit, workflow, and checkpoint state.
  • Govern writes, provenance, retention, deletion, tenant isolation, integrity, and poisoning controls.
  • Trade-off: continuity and personalization versus privacy and state-management risk.

Agent Runtime

Agent Orchestration

  • Topology, planner/workflow graph, state machine, handoffs, supervisor-worker coordination, parallel/sequential execution, retries, checkpoints, and completion control.
  • Orchestration styles include graph/stateful workflow, role/team, workflow-first enterprise, handoff/delegation, hybrid agent+workflow, and tool-centric loops.
  • Implementation examples: LangGraph, CrewAI, Microsoft Agent Framework, OpenAI Agents SDK, Google ADK, Claude Agent SDK, or equivalent/custom orchestration.
  • Trade-off: flexibility and autonomy versus determinism, state complexity, observability, and control.

Decision Plane

  • Bounded routing, classification, prioritization, tool/agent selection, and escalation.
  • Mechanisms: deterministic rules, classifiers, structured LLM decisions, specialized decision models such as Jev/equivalent, hybrids, and human decisions.
  • Decision output proposes what should happen; policy/authorization independently determines whether it may happen.

Tool & Action Surface

  • Read-only, write, customer-facing, financial, privileged, cloud-admin, code-execution, browser/computer-use, and external side-effect actions.
  • Model tool registry, schemas, scopes, action criticality, transaction boundaries, and completion evidence.
  • Trade-off: operational leverage versus blast radius and misuse risk.

Runtime & Containment

  • Sandboxing, network/egress boundaries, runtime credentials, resource quotas, loop/time/token budgets, kill switches, pause/resume, rollback/compensation, and quarantine.
  • Containment must stop unsafe execution without depending on the compromised reasoning path.

Identity & Trust

Agent Identity & Delegation

  • Unique workload identity, human/agent delegation chains, on-behalf-of context, capability attenuation, expiration, revocation, and attribution.
  • Do not use shared human credentials as agent identity.

Authorization & Policy Enforcement

  • Separate Policy Decision Point (PDP), Policy Information Point (PIP), Policy Enforcement Point (PEP), and resource-side enforcement where appropriate.
  • Model proposals, decision-model outputs, human approvals, and protocol connectivity do not themselves grant authorization.
  • Apply step-up, deny, modify, defer, least privilege, and action receipts for consequential actions.

Human Oversight

  • HITL for decision participation/approval; HOTL for runtime supervision; human-over-the-loop for supervisory control across autonomous loops; HATL for governance/accountability.
  • Prefer risk-adaptive oversight based on action criticality, reversibility, confidence, and operational scale.

MCP / A2A Trust Boundaries

  • Model host/client/server/gateway and agent-to-agent boundaries explicitly.
  • Authenticate peers, constrain capability discovery, preserve message/task provenance, validate schemas, and authorize every protected resource/action independently.
  • Protocol connectivity is not business authorization.

Security & Operations

Secrets, Credentials & Cryptography

  • Credential broker, short-lived tokens, secrets isolation, key management, encryption, workload-bound credentials, and rotation/revocation.
  • Keep durable secrets out of prompts, memory, logs, and model-visible context.

Observability & Incident Response

  • Correlated prompt/retrieval/model/decision/policy/tool traces, action receipts, anomaly detection, cost/loop telemetry, and SIEM integration.
  • Design runbooks for kill switch, credential revocation, tool disablement, memory/index quarantine, and forensic reconstruction.

Evaluation & Adversarial Testing

  • Golden tests, red-team scenarios, prompt/tool attacks, RAG quality, authorization-negative tests, regression testing, behavior drift, and release gates.
  • Evaluate task success and independent completion evidence, not merely fluent outputs.

AI Supply Chain & CI/CD

  • Model/artifact registry, dependency integrity, signed/promoted artifacts, build provenance, framework/SDK governance, scanning, rollback, and controlled deployment.
  • Framework choice introduces supply-chain and version-drift risk that must be governed independently from architecture choice.

Governance & Assurance

Governance / Risk Traceability

  • Trace business driver → requirement → security service → architecture component → control → implementation → test/evidence.
  • Record accountable authority, responsible operators, exceptions, residual risk, and reassessment triggers.

Evidence & Assurance

  • Preserve control evidence, policy/action receipts, approvals, test results, release decisions, incidents, and continuous-assurance telemetry.
  • Evidence should demonstrate both control design and operating effectiveness.

AI Risk Governance

Purpose: translate AI RMF governance intent, the NIST AI 600-1 generative AI risk taxonomy and the EU AI Act into design inputs, evidence requirements, control priorities, and operational decision gates.

AI RMF Operating Functions

Use Govern, Map, Measure, and Manage as the lifecycle operating model for AI risk decisions, ownership, assessment, monitoring, and treatment.

Trustworthiness Characteristics

Design for valid and reliable behavior, safety, security and resilience, accountability and transparency, explainability and interpretability, privacy enhancement, and harmful-bias management.

NIST AI 600-1 GenAI Risk Taxonomy

Screen the design for generative-AI risks unique to, or exacerbated by, model generation, retrieval, tool use, agentic execution, and synthetic content creation. Twelve risk areas from the July 2024 Generative AI Profile.

EU AI Act Obligations

Classify the system under the EU AI Act risk tiers. Prohibited practices must be blocked at design time. High-risk AI systems require conformity assessment, technical documentation, human oversight, bias testing, accuracy and robustness standards, and registration in the EU database before market placement.

Risk-to-Control Traceability

Each high-risk AI behavior should trace to questionnaire evidence, design factor, security EPIC, pattern selection, trade-off rationale, test case, and monitoring signal.

Governance Evidence

Capture model card inputs, data lineage, prompt versions, retrieval source policy, evaluation results, red-team findings, approval decisions, incident records, and exception handling.

Decision Gates

Require explicit review before production release, model/provider change, new tool enablement, new sensitive data class, increased autonomy, or expanded user population.

Sector Regulations

Layer sector-specific frameworks — HIPAA, PCI DSS, SOX, GDPR, DORA (financial AI), MiFID II — over the AI-specific governance baseline. Requirements may restrict model hosting, data residency, explainability, and human oversight depth.

EU AI Act Risk Classification

The EU AI Act (Regulation 2024/1689) entered into force 1 August 2024. Prohibited-practice provisions have applied since February 2025; GPAI obligations since August 2025; transparency obligations apply from August 2026. Current transition dates for high-risk systems are phased, including Annex III high-risk systems from 2 December 2027 and high-risk systems embedded in regulated products from 2 August 2028. Validate the current implementation timeline for the specific system category before deployment.

Agentic Security & Governance

Purpose: apply a conditional agentic-security operating model when an AI workload uses tools, persistent memory, delegated authority, autonomous actions, external agents, or state-changing execution.
MCP provenance: Model Context Protocol (MCP) was created and open-sourced by Anthropic in November 2024 and donated in December 2025 to the Linux Foundation's Agentic AI Foundation (AAIF) for vendor-neutral stewardship.
Architecture status: author-created integration. AARM supplies normative runtime requirements; ATF supplies trust, governance, and autonomy concepts; MAESTRO supplies cross-layer threat modeling; CoSAI supplies selected secure-design guidance; CSA supplies enterprise assurance and control integration.

How the Architecture Fits Together

AARM — Runtime Enforcement

Intercepts every material agent action, evaluates intent and context, returns ALLOW, DENY, MODIFY, STEP_UP, or DEFER, and records attributable receipts.

ATF — Trust & Autonomy Governance

Defines identity, behavior, data, segmentation, incident-response boundaries, and the maximum autonomy level an agent may earn.

MAESTRO — Threat Modeling

Decomposes the agentic system across seven layers, identifies layer-specific and cross-layer threats, and prioritizes mitigations.

CoSAI — Secure Engineering

Provides secure-by-design practices, agentic IAM, MCP security, shared responsibility, incident response, and artifact-integrity guidance.

CSA — Enterprise Assurance

Maps threats and controls into CSA AICM v1.1 for AI-specific controls and CCM for cloud controls, plus audit evidence, risk management, security operations, compliance, and continuous assurance.

Agent Execution Control Loop

1. PerceiveAcquire and normalize trusted/untrusted inputs with provenance and classification.
2. ReasonInterpret the task and determine whether a direct response is sufficient.
3. PlanCreate bounded steps, budgets, dependencies, and delegation decisions.
4. Authorize & ActApply AARM/policy checks, then execute approved tools with least privilege.
5. Observe & VerifyInspect tool results and independently check task acceptance criteria.
6. Continue / StopLoop only within budgets; on pass return verified output, otherwise retry, escalate, or fail safely.

Human Oversight Architecture

HITL — Human in the Loop

Human approval is part of the execution path before defined material actions proceed.

HOTL — Human on the Loop

The system acts within approved boundaries while a human monitors, can override, and can trigger containment.

Human over the Loop

A supervisory human oversees one or more autonomous loops, changes operating boundaries, reduces autonomy, disables tools, or stops workflows without approving every transaction.

HATL — Human at the Loop

Humans establish policy, accountability, autonomy limits, lifecycle governance, and escalation requirements.

Risk-Adaptive Oversight

Oversight changes by action criticality: low-risk actions may be autonomous, reversible changes monitored, and financial/privileged actions stepped up to explicit approval.

Human Oversight Definitions

HITL — Human in the Loop

A human decision or approval is required before the defined action executes.

HOTL — Human on the Loop

The system may act within approved boundaries while a human monitors, can override, and can trigger emergency containment.

Human over the Loop

A supervisory human oversees one or more autonomous loops and can reduce autonomy, change policy, disable tools, or stop workflows without approving every transaction.

HATL — Human at the Loop

Humans govern policy, autonomy boundaries, escalation, review, and lifecycle accountability rather than approving every action.

Closed-Loop Control Flow

1. Secure ConstructionCoSAI and system design define identities, tools, memory, protocols, trust boundaries, and containment.
2. Threat DecompositionMAESTRO identifies threats across the seven-layer agent architecture and cross-layer attack paths.
3. Trust RegistrationATF sets autonomy level, operating boundaries, monitoring expectations, and promotion/demotion criteria.
4. Runtime DecisionAARM intercepts and evaluates each proposed action using identity, intent, context, policy, and risk.
5. Bounded ExecutionApproved actions run with least privilege, sandboxing, network/data boundaries, and human approval where required.
6. Assurance FeedbackReceipts, telemetry, incidents, and evaluations feed CSA assurance and ATF autonomy reassessment.

Secure Production Blueprint

Production AI design should be layered: operations and scale, data and retrieval integrity, guarded inference, and constrained agentic execution. The design should map threats, controls, and operational runbooks before implementation choices are finalized.

Layer 1: Operations, Resilience, and Scale

  • Capacity planning, quotas, request scheduling, autoscaling, cost controls, high availability, and degraded modes.
  • Design triggers: high concurrent requests, strict latency targets, provider rate limits, GPU scarcity, or business-critical workflows.

Layer 2: Data Integrity and Vector Isolation

  • Input validation, source provenance, chunking governance, embedding drift control, vector-store authorization, and tenant isolation.
  • Design triggers: enterprise RAG, regulated records, frequent knowledge updates, or per-user document authorization.

Layer 3: Guarded Inference Pipeline

  • User input capture, prompt policy, semantic cache, retrieval routing, model inference, output validation, and redaction.
  • Design triggers: sensitive prompts, customer-visible outputs, hallucination risk, or response quality requirements.

Layer 4: Agentic Governance and Runtime Control

  • ATF trust boundaries and autonomy level; AARM action interception and decisions; agent identity/delegation; tool and MCP registry; sandboxing; approval gates; receipts; kill switch.
  • Design triggers: agents, external tools, write actions, cloud operations, customer-impacting tasks, delegated authority, or multi-agent workflows.

Layer 5: Continuous Agentic Assurance

  • MAESTRO threat reassessment, behavior and semantic-drift monitoring, red teaming, incident response, control-effectiveness evidence, autonomy promotion/demotion, and provider/tool change review.
  • Design triggers: persistent memory, Level 3/4 autonomy, privileged actions, third-party agents, regulated workflows, or continuously changing tools and models.

Observe-Think-Act Threat Surface

  • Observe: memory/context, retrieved documents, and external inputs. Think: prompt planning and reasoning chain. Act: tool calls, APIs, code, and workflow execution.
  • Control each stage with validation, authorization, monitoring, and containment. No single defense is sufficient for indirect injection.

Diagnostic Playbook

  • Symptoms: peak-traffic crashes, retrieval threat exposure, instruction override, fine-tune drift, confabulation (hallucination), context saturation, and production performance or distribution drift.
  • Responses: inference scaling, retrieval isolation, prompt/policy controls, retrieval refresh, evaluation-set updates, model-routing changes, and retraining or fine-tuning when justified. Regularization is a training-time technique, not a runtime production remedy.

AI Engineering Coverage

  
This design lens incorporates AI engineering topics that materially affect architecture: LLM fundamentals, prompt engineering, RAG, agents, fine-tuning, embeddings, LLMOps, evaluation, safety, multimodal AI, and infrastructure scalability.

  

    
LLM Fundamentals
Account for tokenization, context window, temperature, structured output, KV cache, model size, and model behavior constraints before capacity and UX targets are finalized.

    
Prompt Engineering
Design prompt templates, system instructions, output parsers, prompt chaining, edge-case handling, multilingual behavior, and prompt injection defenses as versioned assets. No perfect injection defense exists — design for detection, not prevention alone.

    
Retrieval-Augmented Generation
Evaluate chunking, embeddings, hybrid search, reranking, metadata filtering, source attribution, GraphRAG, freshness, access control, and multi-hop retrieval. Authorization at retrieval time is mandatory — not post-generation.

    
AI Agents and Agentic Systems
Design tool definitions, Model Context Protocol (MCP) boundaries, ReAct or plan-and-execute flows, memory, agent loop termination, orchestration, recovery, and human approval.

    
Fine-Tuning and Model Adaptation
Choose prompt engineering, RAG, LoRA, QLoRA, full fine-tuning, distillation, or (rarely, with research-scale infrastructure) continual pre-training based on data stability, hardware, latency, cost, privacy, and forgetting risk.

    
Vector Databases and Embeddings
Plan embedding model choice, dimensionality, index strategy, metadata, multi-tenancy, drift, quantization, and search-quality benchmarking. Embeddings are derived sensitive data where source data is sensitive.

    
LLMOps and Production AI
Operationalize model serving, prompt versioning, model rollback, feature flags, rate limiting, token streaming, cost controls, model routing, and provider fallback.

    
Evaluation and Testing
Use golden datasets, regression tests, red teaming, hallucination detection, factual consistency checks, RAG metrics, agent evaluation, and continuous evaluation.

    
Safety, Ethics, and Responsible AI
Address hallucination, bias, privacy, explainability, misuse, copyright, audit trails, incident response, EU AI Act classification, high-risk AI conformity, and user appeal workflows.

    
Multimodal and Infrastructure Scale
Extend architecture for images, tables, audio, video, multi-modal RAG, GPUs, batching, speculative decoding, quantization, request priority, and edge or on-device deployment.
